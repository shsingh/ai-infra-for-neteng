[manifests 11–13](https://github.com/shsingh/ai-infra-for-neteng/blob/master/PLAN.md#6-manifest-specifications) · guide: `docs/labs/lab11-ai-sec.md` (produced in build stage 9). Reference implementation for the

## Scenario

**Situation.** Module 8 gave the model pool a cache-aware picker and Module 7 gave tenants
egress identity and ACLs. The pool nevertheless accepts arbitrary prompts from anywhere on
the campus network, and prompt injection against a research model is a live risk: a
poisoned prompt that exfiltrates a partner's fine-tuning dataset is a data-governance
incident, not a performance bug.

**Request.** The security office requires screening before the model is reached: deploy
the prompt-safety stack (the Laya decision model hosted by the Nova rule engine) at the
edge, with per-tenant policy tiers, and verify it against the seed jailbreak corpus.

**Success criteria.** Hostile prompts return 403 at the edge before any pool or picker
state is touched; benign prompts pass unchanged; the per-tenant verdicts and 429s are
visible in the Nova and TMM logs; the catch-rate comparison against a plain string filter
is understood, including its limits.
## The pieces

- **Laya** — an open-weights decision model: a small classifier (not a chat LLM)
  purpose-trained to answer injection / jailbreak / benign about a prompt. Runs on
  CPU-class hardware; the "smart if-statement" pattern — cheap enough to run inline on
  every request.
- **Nova** — the prompt-rule engine that hosts the decision model and the rule set:
  block/flag/pass policies per tenant class, loaded from declarative files (the `.nov`
  format) — in Git, like everything else.
- **The edge (TMM)** — the enforcement point: block returns 403 before the InferencePool;
  pass routes to the pool exactly as Module 8 built it.

## Why at the edge and not inside the picker (the argument the module exists to teach)

Students may ask: the EPP already reads every request — why not prompt-screen inside the
Inference Extension? Have students argue the question, then establish these points:

1. **Wrong plane, wrong job.** The picker is a cache-aware load-balancing control
   function: its contract is "pick the best endpoint," and its failure mode is
   availability-oriented (fail open to some endpoint). A security control that fails open
   is not a security control. The edge is built to fail closed (deny) — that is what an
   enforcement point is for.
2. **Blast radius of a miss.** If screening lives at the picker, a hostile prompt has
   already been accepted by the Gateway, allocated a flow, entered the inference path —
   it consumed edge capacity and reached tenant-internal plumbing before anyone looked.
   At the edge, the block happens before the cluster: no flow, no egress translation, no
   picker metric, no cache footprint. Dropping a packet at the edge is cheaper than
   unwinding a session mid-pool.
3. **Ordering is the security architecture.** Edge screening (TMM) -> L7 routing (picker)
   -> model. Each layer does one job; putting policy inside the picker couples security
   releases to inference-extension version churn. Security policy changes without
   touching the serving path — the same argument as every firewall-in-front-of-the-server
   design the class has ever built.
4. **The LTM parallel.** Experienced LTM operators make the same argument from
   practice: the WAF sat at the VIP, not on the server. The same principle applies one
   layer further up the stack.

## Hands-on — wire it up and attack it

1. Deploy Nova with the Laya decision model (pre-staged image, CPU-class deployment;
   images pinned by digest at build time) and load the seed prompt rules
   (`manifests/12-nova-rules.yaml` — block/flag/pass per tenant class).
2. Route through it: update the tenant-ai HTTPRoute so /v1/* traffic passes the Nova
   service before the InferencePool backend — the edge still terminates and forwards;
   Nova classifies inline (`manifests/13-httproute-ai-sec.yaml`).
3. The attack demo: `nix run .#m12-attack` fires the seed jailbreak corpus
   (instruction-override, role-play, encoded payloads) through the Gateway. Observe:
   malicious prompts -> 403 from the edge with the verdict logged; benign prompts -> pass
   to the pool and answer normally.
4. Verify the planes trace: `kubectl logs -n tenant-ai deploy/nova` shows the
   classification; the TMM access log shows the 403s; per-pod counts on the simulator
   show zero requests from blocked prompts — the pool never saw them.
5. Compare with the pattern-matching alternative: the same corpus against a plain iRule
   string filter (Module 6's Irule CR) — the catch rate falls sharply on paraphrased
   attacks. Pattern matching blocks yesterday's jailbreaks; the decision model catches
   the shape of them. Framing: classifiers also have false-alarm rates — that is
   what the flag tier is for.

## Planes check

Module 8 added a control-plane function for performance (the picker); Module 12 adds one
for policy (the screen) — both decided at L7, both enforced by the same data plane, both
declared on the same management plane. Two new control functions, one architecture.
