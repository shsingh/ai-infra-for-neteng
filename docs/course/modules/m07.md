# Module 7 — Traditional Load Balancing: L4Route, Egress, Firewall

Scenario reference: [case study module m07](../case-study.md) · build outputs:
[manifests 04–06](https://github.com/shsingh/ai-infra-for-neteng/blob/master/PLAN.md#6-manifest-specifications) · guide: `docs/labs/lab06-traditional-lb.md` (produced in build stage 9).

## Scenario

**Situation.** Long-standing classical requirements arrive on the new platform: TCP/UDP
services for the genomics cluster, per-tenant egress identity for SNAT, and ACLs between
research divisions.

**Request.** Deliver all three as declarations — an L4Route-backed Gateway listener, an
EgressGateway per namespace, and FwPolicy/FwRulelist attached via SecPolicy — and verify
them in the data plane.

**Why it matters.** Classic LB was always mostly data-plane work; this module shows the
same discipline under the declarative model, which is also the direct answer to "do we
need Kubernetes for plain TCP services?"

**Success criteria.** TCP connect works through the L4Route listener; egress identity is
verified per namespace; an ACL block is observed in the data plane and proven by the log
stream.

## Hands-on

1. **TCP service behind L4Route:** `kubectl apply -f manifests/04-l4route-gateway.yaml`
   (Gateway TCP listener + L4Route -> backend Service), then `nc -vz <vip> <port>` against
   the listener. One L4 route per listener — the constraint, noted. The data plane doing
   what it has always done: accept, load-balance, forward.
2. **Egress identity with EgressGateway:** `kubectl apply -f
   manifests/05-egress-gateway.yaml` — namespace-scoped egress identity; the audit anchor
   the data-governance and partner-agreement people ask about. Every SNAT translation is
   data-plane state created under a management-plane declaration — same as automap ever
   was.
3. **Firewall/ACL:** `kubectl apply -f manifests/06-fw-policy.yaml` (FwPolicy/FwRulelist
   attached via SecPolicy). Rule = src/dst/service/action — instantly familiar. Test the
   block: curl from a client pod to the VIP, observe the drop, find it in the log stream
   (LogProfile/LogHslpub to the log sink). The drop happens in the data plane; the log
   proves it; the policy lives in Git.
4. **Persistence and health:** backend health = Kubernetes probes, not BIG-IP monitors —
   the real conceptual break, taught explicitly; probe checks move to the platform.
   (Module 8 adds the pool that DOES need adaptive decisions — handled by the endpoint
   picker.)

## Break-fix drill

Fault `m7-l4port`: the L4Route backend port is wrong — TCP accepts, then resets. Trace:
listener -> L4Route -> backendRefs -> Service port -> endpoint port.

## Planes check

Everything here is data-plane state (SNAT/egress translations, ACL hits) configured from
the management plane (CRs), with the control plane barely participating: classic LB is
mostly forwarding with small control-plane assists, same as it always was. When a
colleague asks "do we need Kubernetes for plain TCP services?", the planes model answers:
the required element is the data plane — and its current form is stronger than tmsh.
